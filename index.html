Just hit it with the hammer.

hammer models an API once — services, operations, schemas, servers — and converts it to and from every format it has to live in. Read a live MCP server, publish it as an OpenAPI document. Read an OpenAPI document, drive it from a terminal. Read a protobuf contract, publish the same operations as agent tools.

The same description, in every direction

Every format is readable and writable. That is the whole contract: whatever a description came from, it can be published as anything else it claims, and reading the result back gives the same description.

FormatRead fromWritten as
openapian OpenAPI 3.x document, JSON or YAMLan OpenAPI 3.x document, JSON or YAML
grpca FileDescriptorSet, or a live endpoint’s reflectionproto3 source, and the compiled descriptor set
connecta live Connect endpoint’s reflectionthe same contract; one IDL, two wire protocols
mcpa live MCP server’s tools, or a published manifestMCP tool definitions, or a manifest
clia cobra command tree, or an existing binary’s --helpa cobra command tree

Conversion is honest about what it cannot carry. A protobuf contract has nowhere to put an HTTP path, so the renderer says so — in a warning the caller can print, not in a silent drop.

Four things you can do in a few lines

No daemon, no code-generation step, and no protobuf requirement on the formats that do not need one.

An OpenAPI document, as a working terminal command

document, err := os.ReadFile("petstore.yaml")
described, warnings, err := openapi.Parse(document, openapi.ParseOptions{})

root, err := cli.Generate(described,
    openapi.NewInvoker(openapi.InvokerOptions{}),
    cli.Options{CommandName: "petstore"})

os.Exit(cli.Execute(root))
// petstore pets get-pet --petId 7

A protobuf contract, published as MCP tools

described, warnings, err := protocontract.NewDescriptor(protocontract.Descriptor{}).
    FromDescriptorSet(descriptorSetBytes)

manifest, err := mcp.Manifest(described, mcp.RenderOptions{})
os.WriteFile("mcp-tools.json", manifest, 0o644)

A live MCP server, published as OpenAPI

described, warnings, err := mcp.Describe(ctx, "https://example.test/mcp", mcp.DescribeOptions{})

rendered, err := openapi.Render(described, openapi.RenderOptions{})
for _, file := range rendered.Files {
    os.WriteFile(file.Name, file.Content, 0o644)
}

A binary you only have the help page of

// Reads the tool's own --help output, recursively, into a description.
described, err := cli.DescribeBinary(ctx, "/usr/local/bin/docker", cli.DescribeOptions{})

// …and from there it can be published anywhere the rest of this page talks about.
manifest, err := mcp.Manifest(described, mcp.RenderOptions{})

What it is made of

Each format is a package with no opinion about how it will be used. The description is the only thing they share, so a new format is a new package and nothing else changes.

PackageWhat it holds
hammerThe description itself: APIs, services, operations, schemas, servers, side effects, and a classified error kind instead of a transport’s status code.
openapiReads, renders, serves and calls HTTP APIs described by OpenAPI documents.
protocontractReads protobuf contracts from a descriptor set or reflection, renders them back, and calls their operations.
mcpReads MCP servers and manifests into the description, renders tool definitions out of it, and invokes tools.
cliBuilds a cobra command tree from a description, and reads a command tree or a help page back into one.
discovery · docsReflection and documentation support: what a live endpoint says about itself, and the prose a contract carries.

Three rules the code is held to

  • No transport in a format package. A package says what went wrong as a classified error; whoever exposes it maps it to a status code.
  • One translation per target. There is exactly one function that turns a description into MCP tools, and everything that renders them calls it.
  • Open identifiers. A format or a transport is a string, not an enum, so a format this library has never heard of is a value it can still index and resolve.
